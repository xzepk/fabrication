# V3.1 review findings and V3.2 corrections

## Critical engineering semantics

1. **4130 mm was named `overall_depth` even though it was reconstructed as 1190 + 1170 + 1170 + 600.** The first three values are a horizontal top run and the last value is a vertical fascia drop, so adding them does not define plan depth. V3.2 stores `top_projection_depth = 3530` and retains `profile_path_length_ref = 4130` as an inferred developed/profile chain pending DWG verification.
2. **The STEP model was a nominal panel-skin model, but the drawing language could be read as fabrication-ready.** V3.2 introduces `geometry_level=NOMINAL_SKIN`, removes any flat-pattern claim, and refuses to substitute a reference face layout for a true production flat pattern.
3. **Net visible panel mass was the only material quantity.** V3.2 separates net visible area/mass from blank area and purchase area; the latter remain unavailable until a fabrication solid, unfolding rules and nesting/waste policy exist.

## Drawing-expression problems

1. V3.1 PDF views were manually redrawn from dimensions rather than projected from the B-Rep. V3.2 uses OCCT Hidden Line Removal (HLR) to derive top/front/end/isometric linework from the same B-Rep used for STEP.
2. V3.1 repeated 14 equal pitch dimensions, creating clutter. V3.2 shows a concise set-out chain: left margin + `14 EQ @ pitch` + right margin, plus one overall dimension.
3. V3.1 called the right-side profile a “typical section” even though no structure/node was modeled. V3.2 calls it an **end nominal-skin profile** and explicitly states that it is not a structural section.
4. V3.1 order-index sheet silently displayed only part of the 56 marks because the loop stopped at the bottom of the page. V3.2 replaces the cards with a 14-bay x 4-zone mark matrix and automatically checks 56/56 mark coverage in the generated PDF.
5. V3.1 used `NTS / parameters true size` globally. V3.2 uses standard per-view scales (1:100 / 1:25 / 1:20) and `AS SHOWN` in the title block.
6. V3.1 used a Linux-only font path. V3.2 uses ReportLab's cross-platform CID CJK font support and does not bundle font files.
7. V3.1 drawing QA was largely declarative (`True` flags). V3.2 re-opens the STEP, audits DXF, inspects the PDF page count/status/text bounds, extracts panel IDs from the PDF and checks full mark coverage.

## Still intentionally unresolved

- Production-grade parsing of the source DWG in this runtime (no ODA/ACadSharp runtime installed here).
- Confirmed material/node/fold rules.
- True sheet-metal fabrication solid and exact flat pattern.
- Survey/field-measurement application.
- Structural subframe, brackets, fasteners, waterproofing/drainage and sealant design.

Those items remain explicit blockers rather than being approximated by the agent.
